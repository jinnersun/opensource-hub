# 前端功能完整性规范

> 对应 Bug 类型 E：前端空值未防御
> 对应 Bug 类型 G：有数据展示无操作入口

## 规则 1：API 返回值防御

所有从 API 读取的数据，在使用前必须判空：

```typescript
// ❌ 错误
stats.submissions.pending  // stats 可能为 null/undefined

// ✅ 正确
stats?.submissions?.pending || 0
```

## 规则 2：数据展示 → 操作入口

每个数据展示区域必须回答："用户看到这个数据后，下一步想做什么？"

| 展示内容 | 必须提供的操作 |
|---------|--------------|
| ETL 状态统计 | 点击跳转 ETL 作业管理页 |
| 翻译任务数量 | 点击跳转翻译任务管理页 |
| 待审核提交数 | 点击跳转提交审核页 |
| 失败项目列表 | 批量重试 / 单条重试按钮 |
| 翻译失败任务 | 一键重试全部失败 |

## 规则 3：状态反馈

每个操作必须有明确的状态反馈：
- 加载中 → 按钮 disabled + spinner
- 操作成功 → 数据刷新 / toast 提示
- 操作失败 → 错误信息展示 + 可重试

## 规则 4：空状态处理

每个列表/数据区域必须处理空状态：
- 无数据 → 显示空状态提示文案
- 加载中 → 显示骨架屏或 spinner
- 加载失败 → 显示错误提示 + 重试按钮

## 规则 5：链接组件

- 内部路由跳转必须用 `@/i18n/routing` 的 `<Link>`
- 外部链接用 `<a>` + `target="_blank"`
- 禁止用 `<a href="/admin/etl">` 而不带 locale 前缀

## 检查清单

```
[ ] API 返回值所有嵌套属性都有 ?. 或判空
[ ] 每个统计数字有对应的操作入口
[ ] 每个操作按钮有 loading / error 状态
[ ] 每个列表有空状态处理
[ ] 内部链接使用 i18n Link 组件
```
